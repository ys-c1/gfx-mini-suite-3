# 斜坡摩擦积分：定步长 → 可变步长 + 静/动摩擦切换

`mini-tile-collide` 新增的摩擦层。原有整格碰撞（`tile.c`）与斜坡几何解算
（`slope.c`）**一行未改**，摩擦层是包在 `slope_move()` 外面的一层。

```sh
make test             # 几何 6 项 + 斜坡 41 项 + 摩擦 1046 项
make friction-report  # 四组斜坡 × 四档帧率 → out/friction_summary.csv + trace
make friction-plots   # → out/friction_report.svg（本报告引用的曲线）
```

## 1. 问题

旧做法是每个外部帧只做一次摩擦判断：加一次重力、走一整步、`slope_move()`
投影掉法向分量、然后按 `μ` 判断这一帧“动还是不动”。由此产生三个问题：

- **结果依赖帧长。** 每帧扣掉的切向速度是 `μ·a_n·dt`，`dt` 一变，同一条
  斜坡的滑行距离、停止位置、停止时刻全都变。
- **临界角附近整块滑走或抖动。** 在 `θ ≈ atan(μs)` 处，一帧之内的重力增量
  `g·dt` 可能大于静摩擦能提供的 `μs·g·cosθ·dt`，于是这一帧判成滑动；下一帧
  速度归零后又判成静止。是否有滑走取决于帧长（见曲线 ③：30/60/240 fps 的
  旧积分轨迹分叉）。
- **能量可能增长。** 单帧把速度清零再叠加下一帧的重力，会出现“越算越有劲”
  的情况，没有任何上界。

## 2. 做法

接口在 `src/slope_friction.h`，实现 `src/slope_friction.c`。

**可变步长。** `slope_friction_step(..., dt, ...)` 接收任意外部帧长，内部取
`n = round(dt/dt_max)`（若 `dt/n > dt_max` 再 +1），把这一帧均分成 `n` 个
等长子步。30/60/120/240 fps 是 `dt_max = 1/240` 的整数倍，子步序列与旧的
每帧一步完全一致——这是平地/墙面结果逐位不变的原因。非整数倍（144 fps）
均分而不是“整步 + 零头”，避免子步网格随帧边界漂移。

**静/动摩擦切换。** 每个子步，先算重力、走一步、用 `slope_move()` 投影掉
法向分量，然后只看切向：

- 子步**开始时**速度在 `V_EPS = 1e-4 px/s` 以内，并且这一步重力带来的切向
  增量在静摩擦锥 `μs·a_n·h` 以内 ⇒ **静摩擦**，切向速度清零，`at_rest = 1`；
  同时把这一步已经累积的切向位移退回（法向钳位保留，脚点仍在面上），
  所以静摩擦锁定期间位移恒为 0，不会以 `O(g·h²)` 的速度蠕动。
- 否则 ⇒ **动摩擦**，切向速度减去 `μk·a_n·h`，并在过零处截断（不反向）。

**不发散。** 两个分支都只减小 `|v_t|`，`slope_move()` 只移除 `v_n`，所以除重力
外 `|v|` 不会增大；零截断保证单步不会把速度符号翻过来。任何 `h`、任何
静/动切换顺序下都非扩张，测试 6/7 在 6 个角度 × 3 档帧长和 600 帧临界角
来回切换下逐帧检查了这一点。

**临界角判定。** 静摩擦锥比较带 `1e-5` 的相对松弛：`θ = atan(μs)` 恰好
落在这条边界上，没有松弛时比较结果由浮点最后一位决定，会在两分支间来回。
带松弛后“临界角”确定性地判为静止。

## 3. 抖动上界

对静摩擦锁住（`at_rest`）的物体，每帧能获得的速度只有一次重力增量，且
`V_EPS` 以下被忽略：

```
|Δv| ≤ g·dt + V_EPS                     (px/s)
|Δy| ≤ ½·g·dt² + V_EPS·dt               (px)
```

两者随 `dt` 线性/二次收紧，`dt → 0` 时趋于 0。函数
`slope_friction_velocity_jitter_bound()` / `..._position_jitter_bound()`
直接返回这两个上界；测试 8 在 30/60/120/240 fps 下测得的实测 `|Δv|` 均为
0，远低于上界（1.25 px/s @ 30 fps）。

## 4. 四组斜坡结果

配置 `friction.cfg`（`μs = 0.6`、`μk = 0.45`、`dt_max = 1/240 s`、`g = 300 px/s²`，
临界角 `atan(0.6) = 30.9638°`）。四档外部帧长 30/60/144/240 fps，每场景模拟 4 s。

| 场景 | 内容 | 期望 |
|---|---|---|
| S1 `s1_hold20` | 20° 斜坡，低于临界角，从静止释放 | 静摩擦一帧内锁住 |
| S2 `s2_chain45` | 45° 连续链条（整条地图对角线），从静止释放 | 一直滑动 |
| S3 `s3_mixed45` | 45° 链条接到水平地面，从静止释放 | 先加速，到平地后动摩擦减速、静摩擦停住 |
| S4 `s4_critical` | 恰好 `θ = atan(μs)`，从静止释放 | 静摩擦锁住，不抖 |

收敛帧 = 从该帧起 `at_rest` 再未变为 0；-1 表示直到结束都未静止。

即静/动切换本身贡献的涟漪。耗时 = 该场景该帧率下 `slope_friction_step()`
的 CPU 时间。

要点：

- **收敛与帧率无关。** S3 在四档帧率下的收敛**时刻**均为 1.55 s 左右
  （最大差 0.017 s，即不足一帧；帧数按 `1.55 / dt` 缩放，因为帧数本来就是
  时间的离散化）；S1/S4 第 1 帧即静止。
- **抖动为 0。** 静摩擦锁住期间 `at_rest` 从不翻转，逐帧二阶差分为 0，

## 5. 原有平地与墙面结果不变

测试 `tests/test_friction.c` 第 1、2 段：把 `μs = μk = 0`（即关闭摩擦，
`dt_max = 1/240`）时，摩擦层与旧积分器（`slope_demo.c` 的每帧
重力 + 一步 + `slope_move()`）在平地和墙面上**逐位相同**（使用 `==` 比较
`float`，120 帧 / 60 帧，全部相等）。摩擦层只是包了一层，不改变几何。

四组新场景也不影响旧的 `tile_solid` / `aabb_vs_tiles`：`tests/test_slope.c`
的 41 项检查继续通过，整格接口完全看不到斜坡/摩擦数据。

## 6. 配置

`friction.cfg`：

```ini
mu_static=0.6
mu_kinetic=0.45
dt_max=0.004166667
gravity=300
frame_dts=0.033333333,0.016666667,0.006944444,0.004166667
duration=4.0
```

读取走 `slope_friction_params_from_config()`：`mu_kinetic ≤ mu_static`、
`dt_max > 0`、`gravity ≥ 0` 有一条不满足就返回 -1，程序以 `bad friction params`
退出；缺失键保持默认（无摩擦、`dt_max = 1/240`、`g = 300`），所以**旧配置文件
不需要任何改动**。

## 9. 已知边界

- 采用的是**半隐式**（先重力后位移）积分，不是辛积分器；能量单调不增但
  不是严格守恒（对摩擦系统这本来就不可积）。
- 144 fps 这类非整数倍帧长有 O(`dt_max`) 的分裂误差，见第 9 段测试；
  把 `dt_max` 减半即可线性减小它。
- 法向载荷用的是 `a_n = g·(−ny)`，即把重力沿法向的分量当作支撑力；对于
  由其它力压向斜面的情形（例如角色主动向下蹬），需要在调用方叠加。
